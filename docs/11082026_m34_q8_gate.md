# M3.4: Q8_0 forward correctness gate (Qwen3.6-27B-Q8_0)

Proves surge's Metal Q8_0 decode of the 27B GGUF is NUMERICALLY correct, not just
coherent (M3.2/M3.3 established coherence). Two gates, both on
`/Users/macmini/models/gguf/Qwen3.6-27B-Q8_0.gguf`. Manual/env-gated: never part of
`make check` (needs the 28 GB GGUF, llama.cpp, and one ~11 min scalar-C CPU forward).

## Gates

- **(A) surge Metal Q8_0 vs surge CPU-ref Q8_0** (`tools/tf_compare_q8.py`).
  Teacher-forced: ONE forward pass over a fixed 68-token prompt (no chat template, no BOS)
  on each path, both reading the same Q8_0 bytes. `surge` (Metal) and `surge-ref` (scalar
  CPU, drives `sg_ref_matvec_q8`) already carry `--logits`, which dumps every prompt
  position's logits as raw f32 `[positions, vocab]`. Gate = 100% top-1 argmax agreement.
- **(B) surge greedy vs llama.cpp greedy** (`tools/xcheck_llama_q8.py`).
  Independent oracle catching a bug shared by both surge paths (which A cannot). Uses
  `llama-simple` (minimal greedy example: no jinja/chat/thinking, respects `add_bos`),
  not `llama-cli`. Tokenizer parity is verified first with `llama-tokenize`. Gate = no
  early systematic divergence (divergence within the first few tokens on multiple prompts).

## Results (2026-08-11, feat/m3-m5)

| gate | result |
|---|---|
| A top-1 agreement | 68 / 68 (100.00%) |
| A max \| mean \|logit delta\| | 1.5736e-05 \| 8.0406e-07 |
| A near-tie disagreements | 0 (min top1-top2 gap 1.98e-2, ~1260x the max delta) |
| A CPU-ref forward | 689 s (10.1 s/position), pure-C double accumulate (no Accelerate) |
| B completions vs llama.cpp | 4 / 4 byte-identical, tokenizer parity OK, 0 divergences |

## Re-run

```
make gate                 # A (regression vs frozen digest) + B; combined verdict
make gate FREEZE=1        # re-freeze the committed Metal digest fixtures
make gate-a               # just gate A ; make gate-b   # just gate B (fast)
```

Override the model or interpreter: `make gate GGUF=/path/to.gguf PY=/path/to/python`
(defaults: the 27B GGUF above and `/Users/macmini/models/dsv4-venv/bin/python`). The
driver `tools/gate_q8.sh` refuses to run while a GPU benchmark (`bench_niah`,
`llama-bench`) is active.

## Frozen fixtures (`tests/fixtures/m3q8/`, committed)

- `metal_digest.f32` (68 x 68 f32): per-position digest of the Metal Q8_0 logits (argmax,
  max, mean, rms, then a 64-wide strided vocab sample; M1 digest layout). The Metal path
  is deterministic run-to-run (fixed-tree reductions), so this is a valid regression
  anchor; a non-freeze re-run re-derives the fresh digest and flags argmax/stat drift.
- `ids.txt` (the 68 token ids, self-describing), `result.json` (gate A), `xcheck.json`
  (gate B). The full `[68, 248320]` dumps (~64 MB each) are gitignored and regenerated.
