# ANE backend, first primitive: publish as a draft PR (plan)

Category: Plan (dated). Date: 2026-09-27. Branch: `feat/ane-backend`. Status: draft PR, not
for merge until the primitive is wired into prefill and gated there.

## What this is

Task A0 (2026-08-28, see the top of `todo.md` and the ANE rows in `docs/c4model.md`): a second
compute path over CoreML that reaches the Apple Neural Engine. `src/ane.m` exposes
`sg_ane_open`, `sg_ane_matmul`, `sg_ane_on_ane`, `sg_ane_shape` and two diagnostics;
`tests/test_ane.c` gates one fp16 linear layer against an independent double-precision oracle
built from the generator's `weights.f16`. The measurement harnesses live in `tools/ane_*.py`
and `tools/machine_census.py`.

It is done and gated on hardware, and NOT wired in: nothing calls `sg_ane_matmul` from
`sg_gpu_forward` or `sg_gpu_prefill`. The next task is splitting prefill GEMM between Metal
and the ANE at a measured ratio, gated on unchanged `gen_ids`.

## How it got here

The work sat uncommitted in a checkout. It was carried over onto a branch cut from main after
PR #2 (`df3b539`): the tracked diff (`Makefile`, `surge.h`, `docs/c4model.md`, `todo.md`)
via `git diff --binary HEAD` and `git apply -3`, plus an explicit list of eight untracked
files. The generated fixture (`tests/fixtures/ane/`, about 4 MB) is not committed; it is
regenerated by `make ane-fixture` and is now in `.gitignore`.

## Changes made while carrying it over

- Personal absolute paths parameterized: `ANE_PY ?= $(HOME)/models/ane-venv/bin/python`
  (and the existing `GGUF`/`PY` gate defaults the same way); the tools' GPU-arm interpreter
  default is `SURGE_GPU_PY`, falling back to `~/models/dsv4-venv/bin/python`, defined once in
  `tools/ane_gemm_probe.py` and imported by `ane_envelope.py` and `ane_vs_all.py`; docstrings
  name the venv by role rather than by path. Comment paths in `surge.h` use `~/`.
- `todo.md`: the A0 entry keeps its ANE content; its venv path is replaced by `ANE_PY`.
- `tools/machine_census.py` checked: it embeds no hostname, serial or user path. At runtime it
  records process command lines of contending jobs (first 110 characters, which can include
  paths or arguments) and the names and UUIDs of booted iOS Simulators into the result it
  returns, so a result file written from it should be reviewed before it is published.

## Review (codex, 2026-09-27) and fixes

Applied:
- `sg_ane_open` formatted its failure messages into the handle it then freed, so every
  failed open (including the ordinary no-fixture SKIP in `make check`) returned a dangling
  pointer that the test then printed. Open failures now use the static fallback buffer.
- `sg_ane_matmul` copied into and out of the CoreML arrays assuming a dense
  `(1, C, 1, N)` layout without looking at the strides. It now checks them and refuses a
  padded layout with an error instead of corrupting data.
- `tests/test_ane.c`: an ABSENT fixture is a SKIP but a fixture that exists and does not
  open is now a FAIL (it used to skip on any open error); non-finite outputs are counted
  and asserted (a NaN never exceeds `max_err`, so an all-NaN result used to pass); the
  weights-size check is now fatal, since the reference loop reads `m*k` halves.
- Docs: measured figures are marked as local runs with uncommitted raw results; "the
  accumulator is wide" is narrowed to what the probe shows (not a sequential fp16 running
  sum; an fp16 tree reduction is not ruled out); the `src/ane.m` row no longer claims no
  per-dispatch allocation (the feature provider is allocated per call).
- `ane-fixture` recipe quotes `ANE_PY` and `ANE_FIXTURE`.
- Round 2: `test_ane` SKIPs only when the fixture is absent (`ENOENT`); any other `access`
  failure is a FAIL with its reason. `surge.h` no longer calls `sg_ane_on_ane()` "the real
  answer". The concurrency figures are marked provisional everywhere they appear (below).
  `ane_envelope.py`'s limiter docstring now points at the 2026-08-15 retraction.

Left open, recorded here:
- `sg_ane_on_ane()` reports the placement the generator saw, from its manifest. It is a
  build-time record, not a check on the running machine, and the test's placement
  assertion checks that record: a fixture copied from another machine reports that
  machine's placement. Build the fixture on the machine that runs the test.
- The concurrency figures (31.7 TFLOPS aggregate, 0.963x and 1.002x retention) are
  PROVISIONAL. `tools/ane_envelope.py`'s `full_machine` starts the GPU's 45 s loop before
  the ANE workers compile and sums independently timed rates, so the overlap window was not
  controlled. The docs now say so; the harness needs one synchronized window after
  compilation and a re-run, which pins the GPU and the ANE and was not done in this sweep.
- `machine_census.py` output can carry local paths and simulator UUIDs (above).

## Verification

- `make check` with no fixture: exit 0, 87605 checks, 0 failures; `test_ane` SKIPs.
- `make check` with a locally generated fixture present (gitignored, not committed): exit 0,
  20 test binaries, 87620 checks, 0 failures; `test_ane` 15 checks, `on_ane=1`, worst
  relative error 1.101e-2 (bar 2e-2), 8 reruns byte-identical. `test_cli_prefill` 11
  cases, `test_cli_bench` 19 cases.
- `test_ane` against a missing fixture: SKIP, exit 0. Against an empty
  `program.mlmodelc`: FAIL with the loader's message, exit 1. Against an unreadable
  directory: FAIL "Permission denied", exit 1.
- `make debug`: exit 0, 83615 checks, 0 failures, no sanitizer diagnostics; `test_ane` is the
  `-DSURGE_NO_ANE` stub there.
- The Python tools were byte-compiled only; the measurement harnesses were not rerun (they
  pin the GPU and ANE for minutes and are not part of `make check`).

## Known limits

- `tools/ane_build_model.py` needs `coremltools` from a venv, which breaks the
  no-third-party rule at build time (not at run time).
- The throughput figures in `docs/c4model.md` and `surge.h` come from the harnesses' runs on
  2026-08-28; no result file from those runs is committed.
